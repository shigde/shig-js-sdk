# Local WebRTC connection dashboard

In a joined lobby, **Stats** opens the connection dashboard for both hosts and guests. It opens a floating, resizable panel without destroying the mixer. Drag the handle (or focus it and use arrow keys) to move it across the browser viewport. Resize at the lower corner. **Detach** moves the same live Angular view into a same-origin browser window; **Dock**, or closing that window, returns it to the lobby. A blocked popup leaves the panel usable and displays a message. Leaving the lobby closes the child window. The browser may choose a tab instead of a separate window. Closing it or leaving the lobby releases measurement collection. Every SDK-created `WebrtcConnection` registers with `WebrtcMetricsService`; other SDK consumers can register an existing RTCPeerConnection with `register(pc, 'send' | 'receive')` and hold an `observe()` lease while displaying `view$`.

`@peermetrics/webrtc-stats` samples existing connections once per second. No HTTP polling, loader, WebSocket, backend upload or database storage is involved. History is in browser memory, limited to 600 samples / ten minutes and 50 connection events; it resets when the last dashboard closes or the lobby connections close. The upstream timeline is cleared continuously. Samples are appended while at least one dashboard document is visible, including the detached window when the lobby tab is hidden. Browser statistics collection may still run while the open dashboard is in a background tab.

The charts show aggregate audio/video throughput, ICE candidate-pair roundtrip time, maximum track jitter and maximum track loss. Incoming loss uses deltas calculated by PeerMetrics. Outgoing loss uses matching remote-inbound RTCP fractionLost, so measurement windows differ; it is absent if receiver feedback is unavailable. No loss value is inferred from locally sent packet counters. Jitter and RTT are converted from seconds to milliseconds. Missing, invalid, initial or stale measurements appear unavailable, not zero. Samples older than five seconds are discarded from the current reading; chart gaps are retained. Resolution, FPS, codec and encoder limitation are shown where provided by the browser. Connection status describes transport state, not a guaranteed media quality score.

Measurements describe this browser's connection to its SFU. Remote feedback describes that opposite endpoint, not another participant's complete browser or the whole cascade. Guest-to-SFU metrics, MoQ/WebTransport paths and backend history require separate future work. The selected local/remote ICE candidate type, address and protocol are retained locally for the connection details; raw RTC reports are not retained. The compact overview uses the heuristic reference thresholds documented below; it does not calculate a MOS or LiveKit quality score.

PeerMetrics 5.9.0 ships JavaScript without TypeScript declarations; `provider/peermetrics.d.ts` documents the subset used by the adapter. Each connection has a distinct collector peer ID to avoid the upstream collector starting duplicate state timers when several connections share one peer ID.

The floating view is mounted under the document body to escape lobby layout containment and restored to its Angular-owned DOM position on destruction. Detaching moves that same host node and copies existing stylesheets; no second collector, application bootstrap, BroadcastChannel or metrics transfer is needed. It depends on the original lobby remaining open.

## Compact overview and assessments

The overview separates transport state from media quality. RTT for the send and receive connections stays visible above a shared throughput chart. Audio uses the left axis in kbit/s (orange), video the right in Mbit/s (blue); sending is solid and receiving dashed. All four series share a selectable 1/5/10 minute time range. Audio and video tables compare send/receive side by side. Codec, transport path, per-track encoder information and events live in technical details. Info buttons provide hover text and expandable explanations for touch/keyboard users.

Media quality uses documented heuristic reference values, not LiveKit's score: loss >= 2%, jitter >= 30 ms, RTT >= 250 ms, or CPU/bandwidth encoder limitation. The same issue must persist across three consecutive comparable samples to produce an impairment warning. Missing/stale feedback, a replaced connection, or initial/sparse samples yield an unknown assessment. A single current spike yields a neutral pending assessment, not a sustained-impairment warning. Low throughput alone is never considered impairment. A positive assessment requires loss/jitter for every reported active media track and RTT on both connections. These indicators do not guarantee end-to-end perceived quality.

## Narrow tabbed panel and teardown

The panel defaults to 390 CSS pixels, constrained to the viewport; the detached window requests 400 pixels. Connection Quality and Media Quality are two compact label/value rows with Good/Poor/Unknown statuses. Explanations expand only through the info buttons. Sending/Receiving tabs select one direction; RTT, audio and video values align right in two-column tables. Per-media graphs and technical details are collapsed initially; direction changes collapse the graphs again. History selection remains shared between both graphs.

Angular's component host now remains in its original view. Only the explicitly owned inner panel is mounted under the document body or in the child window. Destruction removes that panel and any placeholder outright, removes window/pointer listeners, closes the child window and releases the measurement lease. It never reinserts a destroyed component. This supersedes the earlier host-moving approach described above. Regression tests exercise repeated structural @if destruction and style preservation in another real browser document.

## Preview control and track-level values

The statistics control is an icon in the bottom-left preview corner. Hosts project the same control template into the layout editor alongside its fullscreen control; guests get it in the stream preview. The floating panel mounts under the active fullscreen element when needed.

The media tables now list each audio/video RTP track separately with right-aligned names and values. Local track labels resolve through negotiated transceiver MIDs and the existing purpose-to-sender map (Me vs Stream), with browser track identifiers as fallback; receiving labels resolve through the SDP remote-media map (participant name or Stream). Unknown mappings retain a neutral numbered label. Device replacements preserve sender identity. Multiple encodings with the same name get a numbered suffix. Codec and encoder information stays associated with its track. The collapsed graphs continue to show combined throughput for the selected media kind and direction.

Connection details are shared below the direction panel, with distinct Sending and Receiving subsections. Local and remote ICE candidates and protocol are separate fields; a host candidate is described as an endpoint address, not a host participant or proof of an internet-direct route.

Candidate details display the ICE type and its address on separate rows. Addresses may be IPv4, IPv6 or browser-provided hostnames; missing addresses are explicitly unavailable. Only the selected candidate pair is shown, using address (or the legacy ip field). These values stay in browser memory; there is no backend upload.

## Dashboard appearance

The existing order, values, tabs, graph disclosures and per-track structure remain unchanged. The panel uses rounded cards with audio (green), video (purple) and connection (cyan) accents and decorative inline SVG section icons. Panel-local light/dark tokens follow the web client's existing document-level data-bs-theme preference, falling back to the system preference when unset. A scoped MutationObserver keeps the detached panel and its document in sync with theme changes; the observer and system-theme listener are removed on destruction. Styles do not depend on the Angular host remaining an ancestor of the portalled panel.
